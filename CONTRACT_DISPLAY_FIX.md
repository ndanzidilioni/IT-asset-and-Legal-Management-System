# Contract Display Fix - "No contracts found for 2025"

## Problem
After fixing the 422 error, contracts were being created successfully but not showing in the Contract Register list because of field mapping mismatches and year filtering issues.

## Root Causes

### 1. Field Mapping Mismatch
**Frontend expected:**
- `tender_number`, `project_name`, `supplier_contractor`, `contract_amount`, `date_signed`

**Backend returned:**
- `contract_number`, `contract_title`, `party_b`, `contract_value`, `signing_date`

### 2. Year Filter Issue
The backend filtered contracts by `signing_date` year, but contracts without a signing date were excluded even if created in that year.

### 3. API Response Format
The API responses weren't consistently wrapped in `{ success: true, data: ... }` format.

## Solutions Applied

### 1. Updated ContractRegister.js
- **Fixed field mapping** to use backend schema fields
- **Extract tender number** from description field where it's stored
- **Handle paginated responses** properly

```javascript
// Extract tender number from description
const tenderNumber = contract.description?.match(/Tender Number: ([^\n]+)/)?.[1] || contract.contract_number;

// Map to correct fields
<td>{contract.contract_title}</td>
<td>{contract.party_b}</td>
<td>{contract.contract_value ? formatCurrency(contract.contract_value) : '-'}</td>
<td>{contract.signing_date || '-'}</td>
```

### 2. Updated LegalContractController.php
- **Fixed year filter** to include contracts without signing dates
- Checks `created_at` year when `signing_date` is null

```php
if ($request->has('year')) {
    $year = $request->year;
    $query->where(function($q) use ($year) {
        $q->whereYear('signing_date', $year)
          ->orWhere(function($q2) use ($year) {
              $q2->whereNull('signing_date')
                 ->whereYear('created_at', $year);
          });
    });
}
```

### 3. Updated legalApi.js
- **Standardized response format** for all contract endpoints
- Added `{ success: true, data: ... }` wrapper

```javascript
getAll: async (year, status) => {
  const response = await fetch(url, { headers: getAuthHeaders() });
  const data = await response.json();
  return { success: true, data };
},

getYears: async () => {
  const response = await fetch(url, { headers: getAuthHeaders() });
  const data = await response.json();
  return { success: true, data: Array.isArray(data) ? data : [] };
},

getStatistics: async (year) => {
  const response = await fetch(url, { headers: getAuthHeaders() });
  const data = await response.json();
  return { success: true, data };
}
```

## Files Modified

1. **Frontend/src/components/Legal/ContractRegister.js**
   - Fixed field mapping to backend schema
   - Added tender number extraction from description
   - Improved response handling

2. **Backend/app/Http/Controllers/LegalContractController.php**
   - Updated year filter to include contracts without signing dates
   - Uses `created_at` as fallback for year filtering

3. **Frontend/src/services/legalApi.js**
   - Standardized API response format
   - Added proper success/data wrappers

## Testing

After these changes:
1. ✅ Contracts created without signing dates now appear in the list
2. ✅ Year filter works correctly for both signed and unsigned contracts
3. ✅ All fields display correctly (tender number, project name, supplier, amount, etc.)
4. ✅ API responses are consistent across all endpoints

## Data Flow

**Create Contract:**
```
Frontend Form → Map to Backend Schema → Save to DB
tender_number → description field
project_name → contract_title
supplier_contractor → party_b
contract_amount → contract_value
date_signed → signing_date
```

**Display Contract:**
```
DB → Backend API → Frontend Display
description → extract tender_number
contract_title → project_name
party_b → supplier_contractor
contract_value → contract_amount
signing_date → date_signed
```

## Notes

- Tender-specific fields (tender_number, year, date_received, date_vetted) are stored in the `description` field as structured text
- The `contract_number` field is auto-generated by the backend (CNT-YYYY-####)
- Contracts without signing dates are filtered by their creation year
